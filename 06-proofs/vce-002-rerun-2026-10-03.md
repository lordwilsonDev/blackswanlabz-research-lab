# Running FCVE's Lean pipeline: setup, smoke test, and the VCE-002 audit

FCVE ([03-systems/fcve.md](../03-systems/fcve.md), commit `c3704cd`) was set up from a fresh clone on a Linux x86_64 machine, a platform its own README lists as unvalidated, and then used to audit the real Lean theorem behind VCE-002 (`powers_of_two_reach_one`, project commit `409c4c3`). Evidence files: [evidence/vce-002-rerun-2026-10-03/](evidence/vce-002-rerun-2026-10-03/). Claims: [C-060](../CLAIMS.md), [C-061](../CLAIMS.md).

## What was run

1. **Setup** (`scripts/setup.sh --tag v4.34.0 --install-toolchain`) after installing elan 4.2.4 by hand, as FCVE's README directs. It fetched the Lean v4.34.0 toolchain and built `lean4export` and `nanoda_lib` from the pinned commits, including the lab's patched copies. Its own validation passed: the patched `lean4export` equivalence test reported 0 mismatches and the patched `nanoda_lib` parse-equivalence test passed (`patch_validation=PASS` in [setup-record.json](evidence/vce-002-rerun-2026-10-03/setup-record.json)). The doctor then reported READY with 12 warnings (unvalidated platform, a newer Rust than the validated one).
2. **Smoke test** (`scripts/smoke-test.sh`): SMOKE TEST PASSED in 86 seconds. It includes a real audit of a small fixture with the independent checker, a check that a fixture containing `sorry` is rejected, and a check that a full disk is reported as BLOCKED, not as a proof failure.
3. **Audit of the real proof**, after fetching the Mathlib cache (8,906 files) and building the module.

## A failed first attempt, and what it showed

My first run of the audit reported row 6 as FAIL. The cause was not the proof: the audit ran `lake build` for the project's default target, which imports only `Basic`, so the module containing the theorem (which imports Mathlib) was never built and the axiom check found no compiled file to read. Row 6 correctly refused to pass on missing output. After building the module explicitly (`lake build IcoCollatzVerification.PowersOfTwoReachOne`) the audit passed.

Two things are worth the author's attention. First, row 3 reported "lake build succeeded" even though the requested module had not been built; row 6 caught it, but the audit could build the `--module` it was given. Second, the environment probe printed `ram_gib=0.0` on Linux.

## What this does not show

- Rows 7 and 9 were not evaluated: whether the Lean statement means what the claim says is a human judgment, and the kernel-vulnerability review needs the web.
- The much larger VCE-001 check (a 17,464-declaration export containing a 25.6-million-digit literal, which needs the patched tools) was not re-run.
- This tests the audit machinery and the theorem's formal checking on a different platform. It does not test whether Collatz-related claims matter, and VCE-002 itself is a small induction by the author's own description.
- The independent check used the upstream, unpatched tools because this proof's closure is small.
