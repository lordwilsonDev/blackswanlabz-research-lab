# Benchmark Project Selection

## Objective

Select real projects whose question-to-build trajectory is informative enough to test learning compression without confusing elapsed time, organizational delay, or access barriers with learning effort.

## Inclusion criteria

A candidate project should have:

- a clear starting question,
- a concrete build or output,
- enough public evidence to reconstruct requirements,
- meaningful technical or conceptual depth,
- independent verification criteria,
- a defensible reference effort,
- enough structure to define L3–L5 transfer tests.

## Exclusion criteria

Reject projects where:

- the “ten years” is only calendar duration with no effort basis,
- essential success criteria are private and unavailable,
- the task is simply recall of published answers,
- a single answer is assumed correct without a verification mechanism,
- the benchmark would be contaminated by public benchmark memorization,
- the project cannot be independently reconstructed.

## Effort bands

Prefer candidate references near:

- 1 month,
- 6 months,
- 1 year,
- 3 years,
- 10 years,
- 10+ years.

Effort bands are reference classes, not claims about universal learning time.

## Selection record

Every chosen project records why it was selected, historical effort evidence, capability decomposition, verification mechanism, known confounds, contamination risk, transfer opportunities, and expected terrain features.

The first flagship study should favor a project with unusually strong historical documentation and a reproducible final artifact.
